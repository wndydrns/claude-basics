# 3장. 안전하게 쓰기

> [!info] 확인한 날짜
> 2026-10-15 · 공식 문서: <https://code.claude.com/docs/en/permissions>

## 3줄 요약
> [!summary] 먼저 기억할 것
> - 보내기 전에 글과 캡처에서 개인정보와 키를 가립니다.
> - 읽으면 안 되는 파일은 `.claude/settings.json`에 적어서 막아 둡니다.
> - 작업 중 의심되는 일이 생기면 허락하지 말고 멈춥니다.

## 핵심 개념

### 1) 보내기 전 점검
붙여 넣을 글과 캡처 이미지는 보내기 전에 직접 봅니다.

| 보내는 것 | 확인할 것 | 가리는 방법 |
|---|---|---|
| 붙여 넣는 글, 코드 | 이름, 연락처, 주민번호, 이메일, 비밀번호, 키 | "고객A", "[연락처]"로 바꾸기 |
| 캡처 이미지 | 화면 구석의 계정 이름, 주소창과 탭 제목, 메신저 알림, 열려 있는 다른 창, 폴더 이름 | 그 부분을 잘라 내거나 칠하기 |

### 2) 읽기, 수정, 쓰기 막기
작업 폴더 안의 파일은 Claude가 허락을 묻지 않고 읽습니다. `.env`, 비밀번호, 고객 개인정보처럼 읽으면 안 되는 파일은 `.claude/settings.json`에 적어서 막습니다.

```json
{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./고객정보/**)",
      "Edit(./.env)",
      "Edit(./.env.*)",
      "Edit(./고객정보/**)"
    ]
  }
}
```

| 규칙 | 막는 것 |
|---|---|
| `Read(./.env)` | `.env` 파일 읽기 |
| `Read(./.env.*)` | `.env.local` 같은 변형 읽기 |
| `Read(./고객정보/**)` | `고객정보` 폴더와 그 안의 모든 파일 읽기 |
| `Edit(...)` | 같은 경로의 수정과 쓰기 |

폴더 이름만 우리 폴더에 맞게 바꾸면 됩니다. 이 가이드 상위 폴더의 [.claude/settings.json](../.claude/settings.json)에도 같은 규칙이 들어 있으니 참고하세요.

> [!warning] 모든 경우를 막지는 못합니다
> 가장 확실한 방법은 중요한 파일을 작업 폴더에 두지 않는 것입니다.

### 3) 권한 모드
Claude가 행동하기 전에 얼마나 자주 묻는지 정하는 설정입니다.

| 모드 | 동작 | 쓰는 때 |
|---|---|---|
| Plan | 계획만 세우고 파일은 바꾸지 않습니다 | 큰 작업을 시키기 전에 먼저 |
| Manual | 파일 수정과 명령 실행 전에 매번 묻습니다 | 처음 시작할 때, 계획을 확인한 뒤 |
| Accept edits | 파일 수정은 알아서 하고, 다른 명령은 묻습니다 | 익숙해진 뒤 |
| Bypass permissions | 묻지 않고 실행합니다 | 쓰지 않습니다 |

> [!warning] Bypass permissions
> 묻지 않고 실행하는 모드라서 쓰지 않습니다.

### 4) 의심스러울 때
허락 창이 `.env`나 고객 자료를 열겠다고 하거나, 작업 폴더 밖의 파일을 건드리겠다고 하면 의심합니다. 결과에 처음 보는 개인정보나 키가 보일 때도 같습니다.

1. 허락 창이 뜨면 거절합니다.
2. 진행 중이면 정지 버튼이나 Esc로 멈춥니다.
3. "방금 어떤 파일을 읽었어?"라고 물어봅니다.
4. 개인정보를 이미 넣었다면 새 세션을 열고 다시 넣지 않습니다.
5. 키나 비밀번호가 보였다면 그 키는 바꿉니다.
6. 그 파일이나 폴더를 2)의 규칙에 추가합니다.

## 따라 하기
1. 연습 폴더에 `.claude` 폴더를 만듭니다. 안 보이면 파일 탐색기에서 숨김 항목 보기를 켭니다.
2. `.claude` 폴더 안에 `settings.json` 파일을 만듭니다.
3. 위 2)의 JSON을 그 파일에 붙여 넣고 저장합니다.
4. 연습 폴더에 `.env` 파일을 만들고 `API_KEY=가짜값`이라고만 적습니다.
5. 연습 폴더에서 새 세션을 엽니다.
6. "`.env` 파일 내용을 알려줘"라고 시킵니다. 읽을 수 없다는 답이 오면 막힌 것입니다.
7. 권한 모드를 Plan으로 바꾸고 작은 작업의 계획을 받아 봅니다.
8. 계획이 괜찮으면 Manual로 바꿔 진행합니다.
9. 끝나면 아래 점검 목록으로 확인합니다.

### 점검 목록
작업 시작 전
- [ ] 연습·작업 전용 폴더에서 시작했다
- [ ] 중요한 파일은 복사본을 만들어 두었다
- [ ] 비밀번호·키·개인정보·기밀을 입력하지 않았다
- [ ] `.env`와 개인정보 폴더를 `.claude/settings.json`에 막아 두었다
- [ ] 붙여 넣을 글에서 이름·연락처·키를 가렸다
- [ ] 캡처 이미지에서 계정 이름, 주소창, 알림, 다른 창을 가렸다
- [ ] 권한 모드가 Manual(또는 Accept edits)이다

작업 중
- [ ] 허락 창의 내용을 읽고 눌렀다
- [ ] 삭제·전송·결제 요청은 내가 시킨 일인지 확인했다

작업 후
- [ ] 숫자·날짜·이름·출처를 원본과 맞춰 봤다
- [ ] 링크를 직접 눌러 봤다
- [ ] 보내거나 공유하기 전에 사람이 읽었다
