# API 분석

## 절차
1. 사용자가 붙여 넣거나 파일로 준 API 문서와 응답 예시를 읽는다. Swagger(OpenAPI) 내용이면 경로, 파라미터, 응답 구조를 읽는다. 문서에 없는 내용은 추측하지 않는다.
2. 아래 형식으로 정리한다. 문서에서 확인되지 않은 항목은 `확인 필요`로 쓴다.
3. 비개발자도 읽을 수 있게 용어는 처음 나올 때 한 줄로 푼다. 예: 엔드포인트는 데이터를 요청하는 주소.
4. 마지막에 업무에서 쓸 수 있는 곳을 3개 이내로 쓴다.

## 출력 형식
```
# [API 이름] 분석 (문서 확인일: YYYY-MM-DD)

## 한 줄 요약

## 인증
어떻게 접근하는지 (헤더 이름, 토큰 발급 방법)

## 주요 엔드포인트
| 이름 | 주소 | 하는 일 |
|---|---|---|

## 응답 필드
| 필드 | 뜻 | 쓰임 |
|---|---|---|

## 사용 한도와 제한

## 업무에 쓸 수 있는 곳

## 확인 필요
```

## 규칙
- 키, 토큰, 비밀번호는 쓰지 않는다. 문서에 예시 값이 있어도 `<토큰>`으로 쓴다.
- API를 직접 호출하지 않는다. 호출이 필요하면 예시 명령만 보여 주고 사용자가 실행한다.
- 문서 날짜나 버전을 적는다. 오래된 버전(곧 사라질 예정이라고 적힌 것)은 표시한다.
- 숫자(한도, 개수, 시간)는 문서에 있는 값만 쓴다.
- 문서끼리 맞지 않는 곳(설명과 허용값이 다름 등)을 찾으면 `확인 필요`에 적는다.
